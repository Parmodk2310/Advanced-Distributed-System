# v0.7.0 — Verified Kubernetes and AWS Delivery Lifecycle

> Draft release notes. Publish only after the public-readiness PR is merged and
> the final release checklist is complete.

`v0.7.0` packages the seven-phase Advanced Distributed System into a verified,
reproducible delivery lifecycle spanning local Kubernetes and a controlled,
temporary AWS EKS demonstration.

This is the first planned formal GitHub Release. Earlier tags remain development
milestones.

## What this release proves

Phase 7 answers a practical delivery question:

**Can the exact tested system be packaged, scanned, deployed, restarted,
rolled back, promoted to AWS without rebuilding, and then completely torn down
with evidence?**

The verified lifecycle covers that path.

## Highlights

### Immutable supply chain

- Hardened non-root OCI image
- Pinned multi-stage build
- Gitleaks source scanning
- Trivy vulnerability scanning
- SPDX SBOM generation
- Immutable GHCR digest
- Keyless image signing
- GHCR-to-ECR copy without rebuilding

### Kubernetes delivery

- Helm chart for the distributed runtime
- Separate etcd chart for the cloud demonstration
- Three application replicas
- Stateful identity and PVC-backed persistence
- Internal services by default
- mTLS material kept out of Git
- kubeconform schema validation
- Conftest/OPA policy validation
- Pod disruption and network policy controls
- Safe kind lifecycle for local verification

### Recovery verification

- CRDT convergence
- trusted/untrusted mTLS behavior
- persistence across pod restart
- same-PVC reuse
- deliberately unhealthy Helm upgrade
- verified rollback
- post-rollback health and convergence re-check

### Controlled AWS EKS demonstration

- Terraform-managed VPC/EKS/ECR foundation
- GitHub-to-AWS OIDC instead of static long-lived AWS keys
- reviewed plan applied without replanning
- restricted EKS API CIDRs
- one `t3.medium` on-demand worker
- no NAT Gateway
- USD 15 demonstration budget boundary
- three etcd members
- three application replicas
- temporary external endpoint
- immediate teardown after evidence capture
- residual-resource verification

## Limitations

This release does **not** claim:

- multi-AZ or node-level high availability from the AWS demo,
- a permanently hosted production service,
- production SLOs,
- internet-scale capacity,
- multi-region disaster recovery,
- consensus,
- linearizability,
- quorum-durable acknowledgements,
- exactly-once distributed execution,
- distributed ACID transactions.

The AWS demonstration intentionally used one worker and existed only long
enough to produce verification evidence.

## Local verification

After the tag is published:

```bash
git checkout v0.7.0

python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pip install -e .

make phase7-release-gate
```

Do not run AWS workflows unless you intentionally want a temporary cloud
demonstration and have reviewed current cost and safety boundaries.
