# v0.7.0 Public Release Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare a truthful, recruiter-friendly v0.7.0 source and immutable container release without recreating AWS infrastructure or changing repository visibility.

**Architecture:** Keep release metadata changes isolated from GitHub Actions runtime modernization so each risk can be reviewed independently. Preserve historical verification identities while introducing a distinct final release identity that is populated only after the release commit's image pipeline succeeds.

**Tech Stack:** Python 3.12, Markdown, GitHub Actions, GHCR, Trivy, Gitleaks, Syft/SPDX SBOM, Cosign, kind, Helm, Kubernetes.

**Spec:** `docs/public-readiness-checklist.md`

## Global Constraints

- Keep `AWS_PHASE7_ENABLED=false`; do not run AWS plan, apply, or destroy workflows.
- Do not create a tag, GitHub Release, or public visibility change without separate approval.
- Do not delete historical branches unless ancestry and unique commits are reviewed.
- Preserve the Phase 7 demonstration identity `cd89ed476c7898cae9d0cb19158075ccfbd46d86` as historical evidence.
- Release version is exactly `0.7.0`.
- The release image must be built from the final tagged source commit and referenced by immutable digest.
- Do not claim multi-AZ availability, consensus, linearizability, quorum durability, or a permanently hosted production service.
